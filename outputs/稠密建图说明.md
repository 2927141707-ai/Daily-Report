# Gemini 2 L + ROS2 Jazzy + ORB-SLAM3 稠密建图（Pangolin 0.6）

本版本在现有环境上增加关键帧后台录制、版本化位姿快照、独立稠密融合节点、ROS2 保存服务和点云重新加载。运行中可以在 RViz 查看彩色点云；正常结束后自动保存最终结果。生成的是米制彩色点云，不是三角网格、导航栅格或可恢复 SLAM 的 Atlas。

## 依赖和源码

- 原始用户安装：`/home/wmy/slam/ORB_SLAM3`，保留原源码、编译结果和数据集。
- 本次开发核心：`work/ORB_SLAM3_p06`，从上述源码复制，增加线程安全退出和关键帧快照接口。
- Pangolin：`/usr/local/lib/libpangolin.so`，0.6。
- OpenCV：系统 4.6；Eigen：系统 Eigen3。
- ROS2 接入源码：`work/ros2_ws/src/slam3_orbbec`。
- 专用构建工作区：`work/dense_ros2_ws`，src 中的包链接至上述源码；与原来的 0.8 构建产物分开。
- 新启动命令使用 `outputs/setup_dense_slam3.sh`。旧的 `setup_slam3.sh` 属于早先的 Pangolin 0.8 环境，不用于本版。
- ORB-SLAM3、g2o、接入节点统一 Eigen 对齐设置为16字节，使用C++17；解决本地 Pangolin 0.6 与 native AVX 编译组件间的内存分配兼容问题。重新编译应使用下面的脚本，避免单独混用旧库。

只使用现有 OpenCV、NumPy、SciPy 完成点云反投影、体素平均、深度边缘过滤和半径离群点过滤，没有增加 PCL/Open3D/TSDF 依赖。

## 快速启动

在已有相机驱动终端按 Ctrl+C，避免重复占用设备。插好 Gemini 2 L，在桌面终端执行：

```bash
cd /home/wmy/Documents/Codex/2026-11-06/rgb-d-orb-slam2-3
bash outputs/run_gemini_dense.sh rviz:=true
```

脚本自动创建 `outputs/dense_runs/时间戳/`，加载 Jazzy 和 Pangolin 0.6 开发副本，启动相机、SLAM、稠密融合节点及 RViz。不要重复打开相机。首次加载词袋会等待几秒，随后应出现 `SLAM initialized`、`state=2`。

先扫描20～30秒的静态桌面，保持纹理、相邻视角重叠，缓慢移动。回到起点附近后停留几秒，让回环/优化有机会完成。跟踪丢失后产生的独立地图分开保存，不会假设它们在同一个坐标系。

Pangolin 显示稀疏特征地图；RViz 显示 `/orb_slam3/dense_map` 的彩色稠密预览。初始 Fixed Frame 是 `slam_map_0`。地图编号变化时，从 `/orb_slam3/dense_status` 读取 `frame_id`，把 RViz Fixed Frame 改成该值。没有给独立地图发布虚假的单位变换。

若 Pangolin GUI 无法打开，可关闭它，同时保留 ROS2 建图和 RViz：

```bash
bash outputs/run_gemini_dense.sh viewer:=false rviz:=true
```

## 等价手动 ROS2 启动命令

以下命令与启动脚本二选一：

```bash
cd /home/wmy/Documents/Codex/2026-11-06/rgb-d-orb-slam2-3
source /opt/ros/jazzy/setup.bash
source outputs/setup_dense_slam3.sh
source work/dense_ros2_ws/install/local_setup.bash
export SLAM3_RUN_DIR="$PWD/outputs/dense_runs/$(date +%Y%m%d-%H%M%S-%N)"
export ROS_LOG_DIR="$SLAM3_RUN_DIR/ros_logs"
mkdir -p "$ROS_LOG_DIR"
export PANGOLIN_WINDOW_URI=x11://
ros2 launch slam3_orbbec live.launch.py \
  output_dir:="$SLAM3_RUN_DIR" \
  record_dense:=true viewer:=true rviz:=true
```

若已自行正确启动相机，可加 `start_camera:=false`。相机节点默认应为 `/camera/camera`，必须启用 `depth_registration`、`enable_frame_sync`、`enable_depth_scale`，关闭额外的彩色/深度去畸变。接入节点会通过驱动参数服务验证对齐、深度尺度和去畸变配置；不符合要求会拒绝输入并打印错误。

需要把相机与SLAM分开运行时，在第一个终端启动相机：

```bash
source /opt/ros/jazzy/setup.bash
ros2 launch orbbec_camera gemini2L.launch.py \
  enable_color:=true enable_depth:=true enable_ir:=false \
  enable_accel:=false enable_gyro:=false \
  depth_registration:=true enable_frame_sync:=true enable_depth_scale:=true \
  enable_color_undistortion:=false enable_depth_undistortion:=false \
  enable_point_cloud:=false enable_colored_point_cloud:=false \
  color_fps:=30 depth_fps:=30
```

第二个终端执行上面的环境加载和输出目录设置，然后将启动命令改为：

```bash
ros2 launch slam3_orbbec live.launch.py \
  start_camera:=false record_dense:=true viewer:=true rviz:=true \
  output_dir:="$SLAM3_RUN_DIR"
```

先停止第二个终端并等待最终保存，再停止相机。

默认话题：

- `/camera/color/image_raw`：彩色，cv_bridge 转成 BGR8。
- `/camera/depth/image_raw`：已对齐彩色的深度；16UC1按毫米转换，32FC1按米使用。
- `/camera/color/camera_info`：实际标定内参。

输入订阅采用 SensorDataQoS，近似同步最大时间差20ms，缓存有界。RGB/深度尺寸必须相同，CameraInfo必须与RGB一致；不支持裁剪/非平凡binning。标定或分辨率改变后需重新启动。实机不会使用 TUM 参数。图像统一去畸变并缩放至默认宽640，保存内参对应处理后的图像。

## 运行中保存

另开终端：

```bash
source /opt/ros/jazzy/setup.bash
ros2 service call /orb_slam3/save_map std_srvs/srv/Trigger '{}'
```

`success: true` 时，`message` 给出完整保存目录。保存先请求最新的位姿快照并排空图像写盘队列，再由独立融合线程处理。若部分关键帧图像因队列过载缺失，响应会注明覆盖不完整，并在 metadata.json 中列出缺失项。服务不返回“已经排队”冒充保存成功。

无法连接SLAM、空地图、目录不可写、点数超限或写盘失败时返回 `success: false` 和错误原因。同一时刻只接受一个保存任务，重复请求会明确提示忙。保存不停止扫描，但请求快照时会短暂等待已有图像写完；大地图融合会延迟预览更新。

## 正常结束和自动保存

在启动终端按 Ctrl+C，等待：

```text
FINAL MAP SAVED: .../maps/save_.../
```

SLAM先停止并等待后台优化线程退出，再排空PNG队列、输出 `final_snapshot.json`。融合节点收到同一退出信号后，会等待最终快照并保存全部仍保留的地图。不要直接 kill -9、关闭进程或断电；异常中止不会伪造“最终优化地图”，已写入的原始关键帧仍在目录中。

保存结果示例：

```text
outputs/dense_runs/<本次运行>/
  camera.yaml                  SLAM使用的处理后内参
  intrinsics.json              稠密反投影内参和深度单位
  camera_info.txt              驱动原始标定记录
  runtime_config.json          SLAM接入节点参数
  rgb/ depth/                  已录制关键帧PNG（depth为毫米uint16）
  frames.txt                   图像索引，兼容早期离线工具
  latest_snapshot.json         最近运行时快照
  final_snapshot.json          正常停止后的最终快照
  trajectory_live_map_N.txt    在线位姿，仅供诊断，历史值不会回溯优化
  maps/save_<时间>_v<版本>_<随机串>/
    map_N.ply                  各独立地图的彩色点云，单位米
    KeyFrameTrajectory_map_N.txt  此次快照的优化关键帧TUM轨迹
    metadata.json              地图编号、位姿快照版本、点数、过滤配置及缺失图像
    snapshot.json              稳定关键帧标识、位姿、图像路径
    rgb/ depth/                重建所需图像；同文件系统优先硬链接，否则复制
    intrinsics.json camera.yaml camera_info.txt runtime_config.json
```

每次保存使用新目录，不覆盖历史结果。保存目录是可独立移动的重建数据包；里面的RGB-D图像按不可变原始数据使用，不要编辑它们（硬链接可能与录制目录共享内容）。失败的写入保留为隐藏的 `.partial` 目录，不会作为完成的地图显示。

`version` 是位姿快照版本，不是优化器迭代次数。每张地图另有 `change_index`。运行时快照使用地图更新锁采样；不同独立地图不承诺在同一瞬间采样。最终快照在后台优化停止后采样。

## 重新融合及参数

可以用原始录制目录的 `final_snapshot.json` 或保存包中的 `snapshot.json` 离线重新融合：

```bash
source /opt/ros/jazzy/setup.bash
source work/dense_ros2_ws/install/local_setup.bash
ros2 run slam3_orbbec dense_mapping.py "/完整路径/save_.../snapshot.json" \
  --voxel 0.005 --stride 1 --near 0.3 --far 3
```

会创建新的保存包，原图和旧地图保持可用。早期 `outputs/fuse_dense.py` 是仅最终活动地图的v1工具，本版优先使用上述多地图工具。

启动时的主要参数：

| 参数 | 默认 | 用途 |
|---|---:|---|
| target_width | 640 | 跟踪、录制图像宽度 |
| writer_queue_size | 8 | PNG写盘待处理队列，满时丢新任务并记录缺失 |
| snapshot_period | 2.0 | 位姿快照周期，秒；实际点云刷新还受融合耗时影响 |
| voxel | 0.01 | 点云体素边长，米 |
| stride | 2 | 深度像素采样间隔 |
| near / far | 0.3 / 4.0 | 融合深度范围，米 |
| outlier_radius | 0.04 | 点云邻域半径，米 |
| outlier_neighbors | 3 | 最少邻居数，不包含自身；0关闭此过滤 |
| max_voxels | 600000 | 全部地图合计点数上限，超限报错而非悄悄截断 |

例如：

```bash
bash outputs/run_gemini_dense.sh rviz:=true voxel:=0.02 snapshot_period:=3.0
```

融合节点还可通过直接 `ros2 run ... --ros-args -p ...` 设置 `edge_threshold`（3×3深度邻域跳变阈值，默认0.05米，0关闭）及 `max_keyframes`（默认10000）。

## 更新机制与坐标

- 只在跟踪线程识别到新关键帧时将RGB-D送入后台PNG队列。关键帧编号加时间戳作为稳定图像标识；地图合并后图像标识不变。
- ORB-SLAM3快照接口返回每张地图仍有效的关键帧编号、时间戳和Twc，不把内部裸指针交给融合线程。
- 融合节点每次从不可变关键帧RGB-D重新投影，按最新Twc变换。旧位姿产生的点不会永久残留；关键帧剔除、回环修正及合并会在后续快照重建中反映。
- 点云融合任务在独立Python节点的工作线程执行。最多一个最新预览、一个待处理保存任务和一个正在处理的任务。忙时替换旧预览；不会因每个输入帧追加任务而积压。
- 运行中预览会落后于跟踪。版本、地图编号、缺失图像数、队列替换次数和错误都在 `/orb_slam3/dense_status`。
- 每张地图有 `/orb_slam3/dense_maps/map_N`，`/orb_slam3/dense_map` 指向当前活动地图。地图消失后清空其旧预览，不将独立地图叠加。
- `/orb_slam3/pose` 和 `/orb_slam3/path` 是在线位姿/路径；`/orb_slam3/keyframe_path` 与稠密快照一致。
- TF为 `slam_map_N → slam_camera_optical`，不会重复发布驱动的 `camera_link` 等坐标。地图保留SLAM初始相机光学坐标基准，没有IMU重力对齐或机器人底盘外参。

具体变换：ORB-SLAM3的 `Tcw` 将地图坐标变到相机坐标；保存使用 `Twc = inverse(Tcw)`。反投影得到 `p_camera = ((u-cx)*z/fx, (v-cy)*z/fy, z)`，再计算 `p_map = Rwc*p_camera + twc`。相机光学轴为x向右、y向下、z向前；地图初始轴也沿用这一基准，不能把它直接理解为ROS机器人x前、y左、z上的底盘坐标。

## 排查

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic echo /orb_slam3/state
ros2 topic echo --once /orb_slam3/dense_status
ros2 topic hz /camera/color/image_raw
ros2 topic info -v /camera/depth/image_raw
```

- `Input rejected`：检查相机节点名、参数服务、深度对齐/尺度以及标定是否变化。不要为消除提示而直接关闭验证。
- `Waiting for ...`：检查相机是否被占用、USB连接和话题/QoS。
- `RGB/depth dimensions differ`：深度未正确注册，或分辨率不匹配。
- `max_voxels exceeded`：增大voxel、缩短扫描范围，或在明确内存预算后增大上限。
- `partial coverage`：查看metadata中的missing和writer计数；通常是写盘过慢、磁盘错误或队列过载，部分关键帧不能参与融合。
- RViz没有显示：看dense_status的ERROR及frame_id，确认Fixed Frame与点云一致；首次融合需等待。
- 地图出现多份：跟踪丢失后产生独立地图，分别查看；不能仅靠相同数值坐标强行拼接。
- 未生成final_snapshot：SLAM未正常结束；可用已有latest_snapshot离线尝试重建，但它不等同于正常停止后的最终优化结果。
